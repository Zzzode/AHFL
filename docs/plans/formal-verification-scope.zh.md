# 形式化验证职责调整

## 目标与范围

默认验证 Agent 状态、flow 控制模型和 workflow 通用执行义务；用户按需启用
数据合同性质验证。结果区分通用义务、用户控制目标、环境前提、数据合同目标和
运行时检查。同步 CLI、形式化模块、退款示例、规范和教程。

不新增语言语法、持久格式或完整业务数据符号执行；不改变 provider 实现、TLS
依赖或此前 P1 修复。SMT 当前仅证明合同蕴含，不能声称已证明 flow 实现。

## 阶段与所属模块

1. 独立决策：RFC 0028 记录验证选择与失败规则；RFC 0017 记录 SMT 证明边界。
2. Formal：在生成点记录控制规格来源和抽象边界，补独立 Agent 状态检查；修复
   矛盾前提和循环不变量假设，保留现有求解器。
3. CLI：增加显式数据合同验证选择，默认不运行 SMT，分别报告各类结果。
4. 示例与文档：保留退款主示例的外部信任边界，增加可验证金额规则示例。
5. 验证与独立审查：原生单元/CLI 测试、真实求解器、全核构建和相关回归套件。

## 验收证据

- 默认退款检查不产生未请求数据合同的子集警告，也不将其计为已证明。
- 所有 Agent 的控制验证有真实目标；无目标时明确报告未启动求解器。
- 用户时序目标和编译器义务计数分离，抽象/有界结果不冒充完整证明。
- 显式请求的数据目标不支持、unknown、超时、反例或矛盾前提时失败。
- 金额规则的合法公式获证，违规公式提供反例；循环不变量不能相互自证。
- 运行时合同检查明确标为未实现，JSON 命令的 stdout 保持可解析。
- `--verify=off` 保持关闭形式化阶段的语义；旧默认 SMT 调用完成一次迁移。

## 交付与接口影响

- SMV 后端及 formal checker：所有 Agent 生成控制义务，规格携带数值 ID、来源、
  覆盖与假设分类；普通数据合同不进入控制模型。更新相关原生测试与六份 golden。
- SMT 引擎及 solver seam：同一 Agent 的全部合同块聚合前提并检查一致性，目标
  独立求解；错误、unknown、超时和未支持条款不能产生证明。
- CLI：新增 `--verify-data-contracts`，更新选项、帮助、报告和原生集成测试；
  旧默认数据验证调用迁移为显式请求。仅检验 package/sysroot/pattern 静态语义的
  发布证据调用显式关闭形式化阶段，不将无目标检查当作证明证据。
- 共享 IR 辅助模块 `ContractClauseIndex`：复用既有数值 Agent 身份边界判断同域，
  防止合同汇集与条款编号使用不同归属规则；不更改 IR 持久化格式。
- 更新 assurance/core-language 规范、formal-backend 设计、RFC 0017/0028、CLI
  参考、中英文 README 和用户教程。退款主示例保留业务声明并注明边界；新增
  `examples/refund-rules/` 金额规则 package。

共享验证结果结构和 CLI 默认请求行为已按授权调整；DSL 语法、运行时接口和
持久化格式未改变。原先依赖默认 SMT 的外部脚本须添加 `--verify-data-contracts`。
